# Portfolio Project Guidelines

## Project Overview

This is a personal portfolio website showcasing game development, software engineering, and UI/UX projects.

## Technologies

- Use vanilla HTML, CSS, and JavaScript.
- Do not introduce frameworks unless explicitly requested.
- The website will be hosted on GitHub Pages.

## Coding Style

- Always use tabs for indentation, not spaces.
- Prefer readable, maintainable code.
- Reuse existing CSS classes whenever possible.
- Avoid unnecessary duplication.
- Use semantic HTML elements.

## CSS Guidelines

- Store reusable colors, fonts, and shared layout values in `:root`.
- Do not put every CSS property into `:root`.
- Prefer CSS Grid and Flexbox for responsive layouts.
- Keep shared project page styles in `css/projects.css`.
- Preserve the existing appearance of completed pages.

## Design

- Follow the user's Figma designs.
- Do not invent visual changes unless requested.
- When design specifications are missing, explain any assumptions.

## Project Structure

- `index.html`: Homepage.
- `style.css`: Global styles and homepage styling.
- `css/projects.css`: Shared project detail page styles.
- `projects/`: Individual project detail pages.
- `assets/`: Images, icons, and other static assets.

## Working Rules

- Read the relevant existing files before making changes.
- Make only changes relevant to the requested task.
- Explain what files were modified.
- Check for broken relative paths.
- Do not overwrite unrelated user changes.
- Do not commit or push to Git unless explicitly requested.
- Ask before deleting files or making major structural changes.
